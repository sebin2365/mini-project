SafeWork: 작업 전 위험성평가 AI 에이전트

작업 계획을 입력하면 AI 에이전트들이 근거가 달린 위험성평가표를 만들어 주는 서비스

고유번호G041
이름김세빈
소스 코드github.com/sebin2365/mini-project

1. 프로젝트 개요

  • 작업 계획을 한 줄 입력하면, AI 에이전트들이 역할을 나눠 조사하고 위험성평가표(JSA)를 만들어 주는 서비스
    • 입력 예: "내일 T-201 톨루엔 저장탱크 안에 들어가서 용접 보수 작업. 작업자 2명"
    • 출력: 작업 단계별 위험 요인, 위험도(상/중/하), 안전 대책, 근거 규정, 필요한 보호구
  • 마지막 확정은 관리자(사람)가 승인 또는 반려로 결정

※ 사내 안전규정 8종은 실습용으로 만든 가상 데이터임

2. 문제점 및 개선 사항

가. 기존 방식의 문제점과 해결 방법

기존 방식의 문제점해결 방법
물질 정보(MSDS)와 사내 규정을 사람이 직접 찾아야 해서 시간이 오래 걸림 에이전트가 PubChem과 사내 규정 서버(MCP)를 자동으로 조회
예전 양식을 복사해서 쓰다 보니 위험 요인이 빠지기 쉬움 작업 유형을 먼저 분석하고, 유형마다 위험 요인을 하나 이상 넣도록 함
안전 대책의 근거가 분명하지 않음 모든 대책에 근거 규정 번호와 출처를 표시
위험도 판단이 사람마다 다름 위험도(가능성 × 심각도)를 코드가 계산
AI 결과를 그대로 쓰기에는 위험함 관리자가 승인해야 확정되고, 반려하면 의견을 반영해 다시 작성

<표 1> 기존 방식의 문제점과 해결 방법

나. 구현한 핵심 기능

  • 작업 계획 분석: 작업 유형, 화학물질, 인원을 추출. 작업 계획이 아닌 입력은 안내 후 종료
  • 물질 위험 정보 조회: PubChem API에서 GHS 위험 문구를 가져와 한글로 표시 (실패 시 로컬 자료 사용)
  • 사내 안전규정 검색: 직접 만든 MCP 서버에서 작업에 맞는 규정을 검색
  • 위험성평가표 작성: 조사한 내용만 근거로 작성하고, 정해진 형식(JSON)으로 받아 표로 표시
  • 자동 검수: 위험도 계산, 조회하지 않은 규정 번호 삭제, 형식이 부족하면 다시 작성
  • 관리자 승인/반려: 반려 의견을 반영해 v2, v3로 다시 작성. 승인하면 확정되고 인쇄 가능
  • 실시간 진행 표시: 에이전트 진행 단계와 AI가 작성 중인 내용을 화면에 실시간 표시

3. 적용 기술

가. 요구 항목별 적용 현황

(○ 적용, △ 일부 적용, × 미적용)

항목적용내용
Multi-Agent / LangGraph○ 역할이 다른 에이전트 5개로 분리 (작업 분석, 물질조회, 규정조회, 평가표 작성, 검수). LangGraph로 흐름 구성
동적 재계획○ 작업 계획이 아니면 종료, 검수 불합격 시 재작성, 관리자 반려 시 의견을 반영해 재실행
Supervisor 패턴△ 감독 에이전트 대신 정해진 순서 + 조건부 분기로 단순하게 구성
MCP○ 사내 안전규정 MCP 서버 직접 구현. Tool 2개(search_manuals, list_manuals), Resource 1개(규정 원문)
MCP Prompt×미적용
RAG△ 검색한 규정을 AI 지시문에 넣는 방식은 적용. 단, Vector DB가 아닌 키워드 검색
모듈화○ 에이전트(agents), 도구(tools), MCP 서버(mcp_server), 화면(frontend)으로 분리
의존성 주입○ MCP 연결을 그래프에 전달. 환경변수 하나로 LLM 교체 (가짜 / Ollama / OpenAI)
테스트○ 가짜 LLM으로 전체 흐름 자동 점검 23개 항목 통과
LangSmith○에이전트와 LLM 호출 기록을 LangSmith에 저장
LLM-as-a-Judge×미적용. 대신 코드 검수로 형식과 근거를 확인

<표 2> 요구 항목별 적용 현황

나. 기타 적용 기술

  • FastAPI: 백엔드 API 서버
  • SSE 스트리밍: 진행 단계와 작성 중인 내용을 실시간 전송
  • CORS: 화면(5173 포트)과 API 서버(8100 포트)가 달라서 접근 허용 설정
  • Pydantic: AI 답변을 정해진 형식으로 받아 검사
  • PubChem API: 미국 국립보건원의 무료 화학물질 데이터베이스
  • Vue 3: 사용자 화면

5. 교훈

가. 한계 및 트레이드오프

  • 규정 검색을 키워드 방식으로 구현 → 단순하지만, 표현이 달라지면 찾지 못함
  • 에이전트를 순서대로 실행 → 이해하기 쉽지만, 동시에 실행하는 것보다 느림
  • 반려 시 처음부터 다시 실행 → 코드는 단순하지만, 같은 조회를 반복함
  • 평가 기록을 메모리에 저장 → DB가 필요 없지만, 서버를 끄면 기록이 사라짐
  • 위험도는 코드로 계산 → 결과가 일정하지만, 가능성·심각도 점수는 여전히 AI가 판단
  • OpenAI 사용 → 품질과 속도는 좋지만 비용이 발생 (로컬 모델은 무료지만 느리고 정확도가 낮음)

나. 향후 개선 사항

  • 규정을 Vector DB에 넣고 의미 기반으로 검색 (RAG)
  • MCP Prompt 추가, LLM-as-a-Judge로 평가표 품질 채점
  • 물질조회와 규정조회를 동시에 실행
  • DB 저장과 로그인 기능 (작업자 / 관리자 권한 구분)

다. 수행 소감

처음에는 AI에게 "위험성평가표를 써줘"라고 하면 될 줄 알았는데, 근거가 없는 대책이나 없는 규정 번호를 만들어 내는 경우가 있었습니다. 조사하는 에이전트와 작성하는 에이전트를 나누고, 코드로 검수하고, 마지막은 사람이 승인하도록 만들면서 멀티 에이전트를 쓰는 이유를 이해할 수 있었습니다.

수업에서 배운 LangGraph, MCP, FastAPI, LangSmith를 하나의 서비스로 연결해 보면서 각 기술이 어떤 역할을 하는지 알게 되었고, 안전처럼 실수가 큰 분야일수록 AI가 모든 것을 결정하지 않도록 설계하는 것이 중요하다고 느꼈습니다.
